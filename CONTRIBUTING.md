# Contributing

Start with the project README and the relevant architecture or runbook page. Open an issue with a concise description, expected behavior, and a reproducible example before proposing a broad change.

Use the checked-in npm lockfile. Do not commit `node_modules`, build output, `.env` files, real provider credentials, customer data, call recordings, or production logs. Use fictional records in examples and fixtures.

Available checks include `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build`. Note which checks you ran when submitting a change.
